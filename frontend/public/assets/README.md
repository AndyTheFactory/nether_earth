# Visual assets

`manifest.json` maps semantic ids (see `src/render/assets.ts`, `SemanticAsset`)
to image files in this directory. Any id without an entry renders as a
procedural placeholder prism in the ZX Spectrum palette.

Provenance policy: every image added here must be listed below with its
origin. Recreations must follow the original's visual character (2:1 dimetric
blocks, Spectrum colours), not a modern RTS restyle. The one exception to
"no original graphics" is the scenery sprites below (owner decision
2026-09-21: v1 ships only the Spectrum wall/box assets); see their licensing
note.

## Scenery blockers (CR002.5)

The map's `blockers` carry an opaque `kind` (CR002.1). `manifest.json`'s
`scenery` section maps it to an asset, all as data:

- `scenery.kinds`: blocker kind -> scenery asset id;
- `scenery.assets`: asset id -> `sprite` (a key of `SCENERY_SPRITES` in
  `src/render/scenery-sprites.ts`), `footprint` (cells along x, y; 2x2 in
  v1), `height` (the box height the sprite shows, equal to the map height of
  that kind so shadows and sprites agree), optional `ink`/`paper` colours
  (`#rrggbb`, default black on Spectrum yellow), optional `offset`
  (`[right, down]` world pixels, a presentation-only shift of the drawn sprite;
  `scenery.fence` uses it to centre the post, CR003.7).

Pointing a kind at another asset, or an asset at another sprite, changes the
render with no code change. A kind with no valid entry (unknown kind or
sprite, footprint not matching the blocker) is drawn as a grey placeholder
prism. The renderer cuts each sprite into one slice per footprint cell, and
each slice joins the shared depth sort with its cell's key, so occlusion works
as for the per-cell war-base and factory blocks.

| asset id | sprite | Spectrum map element | used for kind |
|----------|--------|----------------------|---------------|
| `scenery.box_low` | `spectrum.box_low` | 17, `La0e2_iso_additional_graphic_27` | `box_low` (height 7) |
| `scenery.box_high` | `spectrum.box_high` | 18, `La2e6_iso_additional_graphic_29` | `box_high` (height 15) |
| `scenery.fence` | `spectrum.fence` | 21, `La050_iso_additional_graphic_26` | `fence` (height 99; map-end posts) |
| `scenery.debris_a` | `spectrum.debris_a` | 6, `L9d9c_iso_additional_graphic_22` | none yet (nuclear debris, #196) |
| `scenery.debris_b` | `spectrum.debris_b` | 7, `L9ef6_iso_additional_graphic_24` | none yet (nuclear debris, #196) |

Evidence (santiontanon/netherearth-disassembly, `netherearth-annotated.asm`):
`Lcd18_draw_map_cell` draws a map element at its 2x2 stamp's anchor cell
(min x, max y; `Lbd91_add_element_to_map`) through
`Lcf2d_draw_sprite_to_buffer`, which takes entry `2 * type` (or `+1`, the same
sprite pre-shifted 4 px) of `Ld6e8_additional_isometric_graphic_pointers`. The
nuclear blast (`Lba44_robots_handled`) turns boxes into element 6 or 7 at
random. The Spectrum screen projection in `Lcf2d` (x = 8e + 4d, y = 8d - 4e -
elevation) is the one `src/render/projection.ts` uses, so the sprites are
drawn at native size with no resampling.

Provenance and licensing: `src/render/scenery-sprites.ts` is generated by
`frontend/scripts/decode-scenery-sprites.py` from the graphic data in
`netherearth-annotated-data.asm` of the disassembly (Apache-2.0 for the
disassembly's annotations). The pixel data itself is the original game's
artwork (Nether Earth, Argus Press Software, 1987), whose copyright the
disassembly's licence does not cover. It is shipped on the owner's decision to
use the Spectrum assets; **redistribution rights for the original artwork are
unverified and need owner sign-off before a public release**. Replacing it
needs only new sprite rows plus manifest entries. The ownership flag sprites
(`src/render/flags.ts`, CR002.6) come from the same source and have the same
status.

## Commander, robot pieces and war-base/factory walls (owner-directed, 2026-09-22)

Extends the CR002.5 scenery exception above to four more categories, on the
owner's direct request (not inferred from a milestone): the commander
figure, the 8 robot-piece silhouettes and the two war-base/factory wall
segments. Same provenance/licensing status as scenery (see below): shipped
on the owner's decision, redistribution rights for the original pixel data
unverified and flagged for public release. Full evidence and the sourcing
decisions are in `_specs/open-questions.md`, "Commander/robot/structure
sprites" (and its "Known gap" note on robot facing); summary:

| category | generated file | decoder | sprite(s) |
|----------|----------------|---------|-----------|
| commander | `src/render/commander-sprites.ts` | `frontend/scripts/decode-unit-sprites.py commander` | `L8e3a_iso_additional_graphic_0`, one frame, no facing (`Lcd83_render_player`) |
| robot pieces (black ink, white paper; tinted bright white for your own units and plain white -- light grey -- for the enemy's, owner request 2026-09-24) | `src/render/robot-sprites.ts` | `frontend/scripts/decode-unit-sprites.py robot` | all 4 cardinal directions of each of the 8 `Ld7b4_piece_heights` pieces (`Ld6c8_piece_direction_graphic_indices` / `Ld740_isometric_graphic_pointers`), selected by the snapshot's `facing` field; several pieces reuse one sprite across 2 or 4 directions, which is the original table's own repetition. The direction-column order (east, west, south, north) is read off `Lcf08_direction_loop`'s set-bit index — see the script's docstring |
| war-base/factory walls (2x2 map elements, one sprite per block -- see `wallBlocks`) | `src/render/scenery-sprites.ts` (`spectrum.wall_low`/`spectrum.wall_high`) | `frontend/scripts/decode-scenery-sprites.py` (same map-element decode as scenery) | `L9914_iso_additional_graphic_18` (height 7), `L9b18_iso_additional_graphic_20` (height 15) — the only two element types `Lbfb2_warbase`/`Lbfe2_factory` use |

Rendering: `src/render/sprite-slice.ts` generalizes the scenery per-footprint-
cell slicing/positioning/texture-caching (originally scenery.ts-only) so
robots, the commander and structure walls share one algorithm. Robot pieces
and the commander are drawn ink-white/paper-grey and recoloured per owner
with PixiJS `tint` (`ownerColor`), matching the Spectrum's single per-player
screen attribute; this replaces the previous placeholder's per-module
rainbow colouring (our own invention, not sourced from the game). War-base/
factory walls are selected per `MapComponent.height` through `manifest.json`'s
`structures.walls`/`structures.assets` (a component height with no entry —
a custom/future map — falls back to the placeholder prism, like an unmapped
scenery kind).

**Not sourced/not wired (documented gaps, not invented):**

- Robot facing: decoded but not drawn (see the "Known gap" note above).
- Factory piece-on-top / war-base "H" decorations (`Lce56_decoration_
  sprite_indexes`): identified and cited in open-questions.md but not
  implemented; the flag decorations it shares a table with are already
  shipped (`flags.ts`, CR002.6).

## Construction-screen module icons (CR002.9)

The eight module icons of the ROBOT CONSTRUCTION screen (and the robot
preview stacked from them) are not image files: `src/ui/construction-icons.ts`
generates them at runtime as 24x24 1-bit sprites from a few isometric
primitives (2:1 blocks with dithered faces, discs, lines). They are an
original drawing made for this project in the style of the original's icons
(one ink colour on black, isometric, measured from
`_specs/milestones/cr002/construction-screen.png`); no sprite data was copied
from the game or its disassembly. Same terms as the rest of this repository.
Colours follow the original's code (`Lcc1f` in the disassembly): fitted
modules white, the others yellow.

## Fonts (CR002.10)

Self-hosted from `frontend/public/fonts/` (served from `'self'`, so the
gateway CSP `default-src 'self'` needs no `font-src` entry). Both files are
generated by `frontend/scripts/build-fonts.py` from one 8x8 bitmap glyph
table kept in that script; regenerate with
`uv run --no-project --with fonttools --with brotli python frontend/scripts/build-fonts.py`.

| file | family | use | provenance / licence |
|------|--------|-----|----------------------|
| `nether-earth-8x8.woff2` | `NetherEarth8` | 8x8 status, menu, HUD and lobby text; crisp at multiples of 8px (16px in the UI) | Original bitmap drawing made for this project; same terms as the rest of this repository. |
| `nether-earth-tall.woff2` | `NetherEarthTall` | the same glyphs at double height (8x16) for titles and the RADAR label; crisp at multiples of 16px | Derived from the glyph table above; same terms. |

The glyphs are a recreation of the *style* of the Nether Earth (ZX Spectrum,
1987) in-game lettering, measured from the CR002 reference screenshots
(`_specs/milestones/cr002/*.png`): capitals only, 7x7 body in an 8x8 cell,
3-pixel stems cut by 1-pixel gaps, titles drawn at double height. No font
data, ROM character set or bitmap was copied from the original game or the
Spectrum ROM: every glyph was drawn by hand for this project. At 7x7 with
3-pixel stems the style leaves little freedom, so simple letters (H, O, U, …)
can coincide with the original's; letters the screenshots do not show (F, J,
Q, Z, most punctuation) are new designs in the same style. Owner review of
this provenance is part of the CR002 visual review. Lower-case code points map to
the capitals, as the original has no lower case.
